# Resume Pro 本地 Agent 接口（可选，实验版）

用户要“把资料导入插件”“让 WorkBuddy 调用 Resume Pro”时读取。仅有原版 0.3.1 时不能直接调用本接口。

1. 从用户工作区定位 `ResumePro本地接口/使用说明.md` 和 `bridge.py`，读取现场版本说明。不要猜安装状态、Chrome 个人资料或模板是否保留。
2. 依次检查 health、status。需要实验版插件、运行中的本地服务和当次页面配对授权。没接通就明确报告缺哪一环。
3. 读取用户提供的 JSON/XLSX/CSV。PDF/DOCX 先按已有简历摄入流程提取并核对，转成 groups/fields 格式，不编造缺项。不把运行数据写进 Skill 安装目录。
4. validate → import → templates 核验数量和导入校验结果 → select 明确选择。已有模板不覆盖；修改资料新增版本。
5. 在用户授权页面 scan，使用实际返回的字段 ID 和 60 秒内 scanId 调用 fill。默认 rules，明确需要模型匹配且数据发送已获授权时才用 ai。
6. result 回读每个任务。超时不重复填写；verified 仅代表即时字段回读，submitted:false 不能记为已投递。
7. 当前接口不支持登录、验证码、敏感字段、勾选协议、文件上传或提交。复杂控件、跨页流程、多段经历新增需单独处理。

验证状态（2026-09-21）：Codex 通过接口在真实 Chrome 中导入四份模板，规则填写本地表单 6/6 并回读通过；国内招聘网站、AI 模式仍待验收。WorkBuddy 已实际调用 health/status/import/select/scan/fill，6 个已有字段 preserved；空字段写入由 Codex 验证。证据在工作区 WorkBuddy接口实测.md 与验收记录.md。

三个验收任务：
- 导入同一份演示 Excel 两次：只有一个相同内容模板，返回 already_present，不改变 API 配置。
- 选定模板后填写本地页：逐项核对成功和漏填，已有值保持，密码和协议不动。
- 插件未连接或页面变化：明确失败，不伪造成功，不重发结果不明的填写命令。
