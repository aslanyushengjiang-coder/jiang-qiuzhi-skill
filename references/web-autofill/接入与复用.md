# WorkBuddy 网申填写：直接调用内置 web-access

用户说“填写网申、自动网申、上传简历、腾讯校招、补齐下拉框”时读取本页。由 WorkBuddy 当前模型理解岗位和资料，调用 web-access 的本地浏览器工具执行。无需另装 Resume Pro、Midscene 或单独配置视觉模型；本机命令和浏览器连接能力仍需实际可用。

## 先读原件

- [web-access Skill 原文](originals/web-access-Skill文档原文.md)：通用工具、启动与页面操作。
- [腾讯站点经验原文](originals/join.qq.com.md)：目标域名为 join.qq.com 时读取。
- [腾讯实战经验原文](originals/腾讯校招网申代填-实战经验.md)：腾讯完整流程、字段清单、失败原因与换人配置。

三份原件按字节保留，不改措辞、代码、换行或历史结果。运行副本在 [vendor/web-access](../../vendor/web-access/SKILL.md)，脚本和引用文档随秋招 Skill 一起安装，无需依赖作者电脑上的路径。校验见 `scripts/verify_web_access.py`。

## 安装后接通

1. 从当前秋招 `SKILL.md` 所在目录确定 `SKILL_DIR`；将 `WEB_ACCESS_DIR` 解析为 `<SKILL_DIR>/vendor/web-access` 的绝对路径。原文的 `${CLAUDE_SKILL_DIR}` 在这套子能力中指 **WEB_ACCESS_DIR**，不是秋招根目录。WorkBuddy 不必预设这个环境变量：把实际绝对路径直接写进每次命令即可。
2. 使用 Node.js 22+；运行 `node "<WEB_ACCESS_DIR>/scripts/check-deps.mjs" --browser chrome`。用户指定 Edge 则用 edge；未指定浏览器时按原文处理，不擅自换账号或浏览器。脚本可能启动本地代理，不把它叫作只读检查。
3. 浏览器未允许调试、需登录或连接确认时，按当前宿主权限和返回信息引导用户完成。不得绕开宿主禁止访问的页面或安全限制。不要自行扩大调试权限；代理保持本机监听。若既有代理已接通正确浏览器则复用，不无故结束其他任务。
4. `exit 0` 后确认工具可用，读取当前目标页；`exit 1/2` 按输出处理。无法接通时只交付字段映射及明确的缺项，不宣称已填写。

## 每次真正填写

- 使用当前用户的岗位链接、已确认资料和匹配方向的简历。原文中的 postid、targetId、姓名、手机号、日期、成绩及 `/Users/a19350/...` 路径都是历史示例，不是当前任务默认值。
- 先建立“字段标签 → 控件类型 → 资料来源 → 待填值”映射；缺少的信息集中补问。示例里的同意调配、部门偏好、证明人等不能照搬给其他人。
- 目标站支持简历自动解析且用户已授权上传时，先核对文件和目标站，再上传；等页面实际出现解析结果后重新扫描字段、经历块和未填项。没有附件或未授权上传时直接填写已确认字段，不强迫先上传。
- 按控件类型处理文本、单选、多选、下拉、级联、日期和附件。腾讯按标签和经历区块定位，避免依赖上传解析前的序号；面板先确认属于当前字段，再选值。参考原件中的等待时间，不能把 Midscene 的 200ms 等待直接套在这里。
- 文本填完再做其他控件交互，回读确认没有被框架重渲染清空；日期需确认控件接受且显示的年月日正确。隐藏、禁用、无选项的字段分别记录，不通过猜值凑完成数。
- 原始 [腾讯示例脚本](examples/4-腾讯网申-批量代填.js) 内含演示 CFG，并会覆盖已有值。仅作为源码参考；先复制到当前用户工作区，按本次真实资料改 CFG 和实际经历数量，移除无资料的步骤，核对与已有字段冲突后才运行。不得直接执行原样示例去覆盖真实简历。
- 原文的“只填号码栏”等技术描述不改变秋招 Skill 的授权边界。证件信息、登录验证码、隐私/真实性声明及最终提交仍交本人；附件仅在已明确授权的范围上传。不得把“继续操作视为接受”当作获得新增权限或法律同意。

## 换站点与验收

通用控件方法可以复用；腾讯 `.subtitle`、Element Plus 选择器、候选城市/部门、文件控件顺序只对记录时的页面有效。其他网站先检查真实 DOM 和控件，再选择方法，不直接套腾讯脚本。经验与现场冲突时以现场为准，新增修正另存工作区，不改三份归档原文。

输出字段总表，逐项区分：已填并回读、缺资料、控件失败、页面隐藏/禁用、需本人处理；附实际附件名和简历版本。动作日志“成功”不等于最终字段保留，完成一次跨区块回读后才计数。草稿与已提交分开记录。

原件记载“63 步成功 62、失败 1”是用户提供的腾讯录屏实战记录，本次整合只验证原文、依赖和调用路径，没有重跑这次真实网申；不承诺所有站点同样成功。
